# Contributing player documentation

[Back to player resources](README.md) · [Play the game](https://survivorpoke.com/)

Useful contributions include clearer instructions, corrected move recipes, accessible explanations, browser-specific troubleshooting and reproducible player reports.

## Suggest a correction

1. Identify the document and the sentence or table row that needs changing.
2. Explain what a player should do or expect instead.
3. Include the game version/date and a public guide, screenshot or reproducible observation when available. A useful single source is welcome; state its context rather than claiming more verification than occurred.
4. Open a documentation issue or a pull request editing only the relevant Markdown.

Keep the game name **PokéSurvivor**, write instructions in plain English, and link to the matching survivorpoke.com guide. Describe a limitation where it affects a player's action. Avoid repeated keywords, promotional claims, fabricated test results or promises that a feature works on every browser/network.

## Report a game problem

Use the gameplay/browser report template. Include device, browser/version, the page address without sensitive parameters, what you clicked, what you expected and what appeared instead. For co-op, explain whether the players were on the same network or different networks and which connection step failed.

Please try the relevant [troubleshooting instructions](docs/troubleshooting.md) first. Do not clear site data as a default repair for a save or connection problem.

Keep passwords, account identifiers, authorization codes, recovery details and complete saves out of public issues. Crop or cover personal information before uploading your own screenshots. Sensitive account questions belong at [hello@survivorpoke.com](mailto:hello@survivorpoke.com).

## Repository boundaries

This repository contains player resources, not game implementation. Contributions should not add game bundles, deployment/cloud configuration, extracted asset packs, player data, executables or account credentials. A bug report documents the problem; it does not guarantee a fix or a response date.

Read [CREDITS.md](CREDITS.md) before contributing third-party material. Credit its source and preserve its conditions. Do not apply a general software license to someone else's game artwork.
